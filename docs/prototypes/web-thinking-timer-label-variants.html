Open Questions · 待确认决策
原型确认后，这些决策将捕获到 change 的 design.md：
  • 计时语义：用前端记录的 thinkingStartedAt（每次思考独立计时），而非 session 累计的 sessionTime。
  • tick 来源：复用后端 1s 的 session_time 广播作为重渲染触发，还是组件内本地 setInterval？（前者零额外定时器，后者更解耦）
  • 停滞阈值：演示用 3s，实际建议 15s？是否需要 thinking_stall 专用事件，还是前端纯基于 delta 时间戳计算？
  • 定格文案：Thought for 23s（Claude Code 风格）vs 保留 Thinking · 23s 仅停止跳动？
  • 多段思考：一轮中 thinking → text → 再 thinking（工具结果后）时，每段独立计时还是累加？
  • WaitingBubble 目前显示的其实也是 session 累计时间——是否顺手修正为本轮等待时长？（可拆成独立 change）
