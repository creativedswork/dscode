ToolCard Spacing v5 — True Root Cause: CSS Cascade Layers

The v3 scoped CSS override never worked. Here's why — and the real fix.

True Root Cause: @layer components cannot override @layer utilities

The scoped CSS rule .tool-card-body-inner pre { padding: 6px 10px; margin: 0 } is inside @layer components in index.css. But the Markdown component's <pre> uses Tailwind classes p-3 (12px) and my-1 (4px), which live in @layer utilities.

CSS cascade layers: utilities always beats components, regardless of specificity.

@layer base { /* preflight resets */ } @layer components { .tool-card-body-inner pre { padding: 6px 10px } } ← LOSES @layer utilities { .p-3 { padding: 12px } .my-1 { margin: 4px } } ← WINS Result: <pre> padding = 12px (not 6px), margin = 4px (not 0)

Why built-in tools have the gap but MCP tools don't:

  • Built-in tools (bash, read_file, grep): formatToolResultForUI wraps result in code fence → renders <pre> with p-3 (12px) + my-1 (4px) = 16px gap
  • MCP tools (plain text): no code fence → renders <p> with 0 margin (Tailwind preflight) = 0px gap

Fix: Move .tool-card-body-inner pre rule out of @layer components to unlayered CSS. Unlayered CSS beats all @layer rules. Also move inline styles on <pre> to a CSS class for border/radius override.
